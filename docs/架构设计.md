# 架构设计

## 1. 数据流

```
                       ┌──────────────────────────────┐
                       │ 待分类1（用户投放）            │
                       └──────────────┬───────────────┘
                                      │
        ┌─────────────────────────────┼──────────────────────────────┐
        │                             │                              │
        ▼                             ▼                              ▼
  ┌───────────┐               ┌──────────────┐              ┌────────────────┐
  │ 扩展名白名单│               │ 扩展名在白名单│              │ 扩展名不在白名单│
  │ 且 MIME 是 │               │ 但 MIME 不是 │              │ (txt/docx/无扩展)│
  │ image/video│               │ image/video  │              │                │
  └─────┬─────┘               └──────┬───────┘              └───────┬────────┘
        │                            │                              │
        ▼                            ▼                              ▼
  读 EXIF 三层                  移到「认不出格式」              原样不动，只提示
        │                     （下坏的 / 文本改名的）
        ▼
  ┌──────────────────────────────────┐
  │ 设备 = Make + Model              │
  │ 时间 = DateTimeOriginal → …      │
  │ 地点 = GPS 2 位小数网格          │
  └──────────────┬───────────────────┘
                 ▼
      主目录\设备\时间\地点\文件
        （复制，源文件保留）
```

去重是独立的一条链路，输入是「待分类1」和「主目录」两组文件：

```
待分类1 ──┐
          ├── 按文件大小分组 ──> 同尺寸组才计算 SHA-256 ──> 同哈希判定重复
主目录 ───┘                                                    │
   │                                                           ▼
   └── 增量读取 .cache/library-hashes.csv（相对路径+大小+mtime 命中则复用）
                                                      重复\时间戳_模式\
```

## 2. 模块划分

| 文件 | 职责 | 不该做的事 |
|---|---|---|
| `src\lib\Common.ps1` | 常量（扩展名白名单）、配置合并、ExifTool 定位、SHA-256、EXIF 取值与格式化、文件清单、安全移动 | 不写业务规则、不决定目录结构 |
| `src\Classify.ps1` | 编排：调 ExifTool → 组装三层路径 → 复制 / 收容 / 写日志 | 不实现哈希、不做去重 |
| `src\Dedupe.ps1` | 编排：两种去重模式 → 维护缓存 → 移动重复文件 → 写日志 | 不改动主目录内容 |
| `tests\run-tests.ps1` | 造夹具 → 以子进程跑真实脚本 → 断言目录与哈希 | 不 mock，测的是真实行为 |

`Common.ps1` 通过 dot-source 引入，脚本不把它当独立入口。之所以不用模块（`.psm1`），是为了让用户 `powershell -File xxx.ps1` 直接能跑，不涉及模块路径、执行策略和版本号。

## 3. 关键决策

### 3.1 为什么三层深度固定

可选方案是「有几层写几层」（缺时间就不建时间目录）。这会让同一个设备下的目录深度不一致，后续任何遍历脚本、备份工具、相册软件都要处理「有的是 2 层、有的是 3 层」。固定三层 + 「无数据」占位，代价是多出一层同名目录，收益是结构可预测。

### 3.2 为什么时间只认 EXIF

`FileModifyDate` 会在下载、解压、拷贝、同步时被改写。用文件时间分类，结果是"按下载顺序归档"，不是"按拍摄时间归档"。同理不使用 `FileCreateDate`（Windows 上复制文件会重置）。

优先级链 `DateTimeOriginal → CreateDate → MediaCreateDate → TrackCreateDate → CreationDate` 覆盖了相机、手机照片、手机视频、剪辑视频四类来源。

### 3.3 为什么 GPS 取 2 位小数

- 0 位 ≈ 111km：太粗，城市会混在一起
- 2 位 ≈ 1.1km：同一景点/街区可以聚在一起，隐私上也不至于精确到门牌
- 4 位以上：会产生大量只差几米的碎片目录

不做地名反查（如「上海市-浦东新区」）是刻意的：需要联网、需要地理编码服务、边界争议多、离线不可用。

### 3.4 为什么必须用 `Copy-Item` 而不是 `exiftool -o`

`exiftool -o 目标目录` 是"读出来再写一个新文件"。它会重排元数据块、可能丢弃不认识的标签，**输出文件的字节与原文件不同，SHA-256 就变了**。这样一来：

1. 主目录里那份的哈希与待分类1 对不上，跨库去重会失效
2. 用户以为在"备份"，实际在"重新生成"

`Copy-Item` 是字节级拷贝，哈希不变，去重才有意义。测试里专门有一条断言守着这一点（`复制后 SHA-256 与原文件一致`）。

### 3.5 为什么先按大小分组

全量哈希 5000 张照片（每张 5MB）≈ 25GB 读取，机械硬盘上要几分钟。按大小分组后，通常只有连拍、副本、同设备同场景的少数文件会撞尺寸，实际哈希量下降一到两个数量级。这是**无损**优化：大小不同 ⇒ 内容必然不同。

### 3.6 缓存键为什么是「相对路径 + 大小 + mtime」

- 只用路径：文件被原地替换（同名不同内容）时会误用旧哈希
- 只用大小：会漏掉等长的改动
- 三个一起：绝大多数真实场景（新增、复制、重命名、删除）都能正确命中或失效

缓存条目在每次运行时按当前主目录重建，所以**删掉的条目自然消失**，不存在"缓存比磁盘还多"的漂移。缓存损坏时（CSV 解析异常）自动重建，不会中断任务。

### 3.7 为什么「认不出格式」按 MIME 判定

早期版本只看 `FileType` 是否为空，结果把 `FileType: TXT`（文本改名成 `.jpg`）放进了主目录。现在的规则是：

```powershell
$mime -match '^(image|video)/'  -or  $fileType -in $MediaFileTypes
```

ExifTool 对真实图片/视频一定会给出 `image/*` 或 `video/*`；给出 `text/plain` 的，无论扩展名是什么都不是照片。

### 3.8 为什么重复文件只移动不删除

去重判定没有任何"相似度"，是严格的字节相等，理论误判率为 0；但用户可能不希望两份同名不同位置的文件被合并（例如两份不同项目里的同一张素材）。移动到 `重复\时间戳_模式\`，保留原文件名，误判可直接移回。

## 4. 数据格式

### 4.1 哈希缓存 `.cache\library-hashes.csv`

| 列 | 类型 | 说明 |
|---|---|---|
| `Size` | int64 | 字节数 |
| `MTimeUtcTicks` | int64 | `LastWriteTimeUtc.Ticks` |
| `Hash` | string | SHA-256 大写十六进制，64 字符 |
| `RelPath` | string | 相对主目录的路径（含子目录） |

### 4.2 分类日志 `.logs\classify_yyyyMMdd_HHmmss.csv`

`源文件, 目标, 设备, 时间, 地点, EXIF时间, 动作`，动作取值：`复制`、`复制(同名加序号)`、`跳过(已存在相同文件)`、`认不出格式(<mime>)，已移出`、`读不出(已移出)`。

### 4.3 去重日志 `.logs\dedupe_yyyyMMdd_HHmmss_<模式>.csv`

`模式, SHA256, 原路径, 重复于, 移到, 时间`；`重复于` 在跨库模式下是 `（主目录）`。

## 5. 边界情况

| 情况 | 行为 |
|---|---|
| 0 字节 / 截断文件 | ExifTool 报错或不返回条目 → 移入 `认不出格式` |
| 有 EXIF 但缺 GPS | 地点层 = `无数据` |
| 手机视频只有 `GPSCoordinates` 字符串 | 解析 `31 deg 14' 4.20" N` 形式得到经纬度 |
| 视频没有 `DateTimeOriginal` | 退到 `CreateDate` / `MediaCreateDate` |
| 文件名含 `[ ]`、`&`、空格 | 全程 `-LiteralPath`，不当通配符 |
| 同一路径重复分类 | 内容相同 → 跳过；内容不同 → 加序号 |
| 主目录里已有内部重复 | 只报告数量，不动主目录 |
| 待分类1 为空 | 打印提示后正常退出（退出码 0） |
| 缓存文件损坏 | 提示后全量重建 |
| 移动时目标重名 | 自动 `_1`、`_2` |

## 6. 已知限制

- **只支持 Windows**：依赖 `cmd` 重定向解决 PowerShell 5.1 的 stdout 编码问题；`Push-Location` + `"."` 的扫描技巧也是为 Windows 命令行编码准备的
- **时间不做时区换算**：手机视频的 UTC 时间需要手动加 `-api QuickTimeUTC=1`
- **地点不做地名反查**：只有坐标网格
- **没有并发**：顺序处理，几千个文件级别的库够用；十万级需要改成并行
- **单设备名可能过长**：超过 60 字符会截断，可能造成两个设备合并

## 7. 可能的演进

1. 可选 `-LocationLookup`：离线 GeoIP/城市边界库，把 `N31.23_E121.47` 映射成「上海-浦东」
2. 并行哈希（`ForEach-Object -Parallel`，需 PowerShell 7）
3. 侧车文件（`.xmp` / `.aae` / `.thm`）跟随主文件一起分类
4. 主目录内部的重复清理模式（`-Scope LibrarySelf`）
5. 分类规则外置成 JSON（可配置多层结构，而不是固定三层）
