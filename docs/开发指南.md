# 开发指南

给后续维护者：代码在哪、怎么改、为什么有些写法看起来很怪（那些都是踩过的坑）。

## 1. 环境

| 需要 | 说明 |
|---|---|
| Windows 10/11 | 脚本用了 `cmd /c` 重定向和 Windows 路径语义 |
| PowerShell 5.1 | 系统自带。**不要用 PS7 的新语法**（`??`、三元、`-Parallel`），否则 5.1 用户直接语法错误 |
| ExifTool ≥ 12 | 只做读取和测试夹具写入 |
| Git | 提交时注意 `.gitignore` 已排除 `config.ps1` 和运行产物 |

验证环境：

```powershell
$PSVersionTable.PSVersion          # 应为 5.1.x
& .\tools\exiftool\exiftool.exe -ver
```

## 2. 代码地图

```
src\
├─ lib\Common.ps1     共用函数（被下面两个 dot-source）
├─ Classify.ps1       分类入口
└─ Dedupe.ps1         去重入口
tests\run-tests.ps1   端到端自测
bin\*.bat             给不想敲命令的人用的包装
```

`Common.ps1` 里的函数一览：

| 函数 | 作用 | 出错时的行为 |
|---|---|---|
| `Get-AppConfig` | 读 `config.ps1` 并与默认值合并 | 读不到/格式错 → 用默认值 + 黄字提示 |
| `Get-ExifToolPath` | 按 Config→PATH→`tools\`→常见位置 找 exiftool | 找不到 → `throw`（无法降级） |
| `Get-FileSha256` | 流式 SHA-256，返回大写 hex | 文件被独占 → 异常上抛，由调用方计入 failed |
| `Test-SameContent` | 长度 + 哈希比较两个文件 | 同上 |
| `Get-ExifField` | 从 `-j -G0` 的对象里按标签名优先级取值 | 缺失/占位 `-`/假时间 → 返回 `''` |
| `ConvertTo-SafeFolderName` | 去非法字符、压空白、截断 60 | 空 → 返回 fallback（`无数据`） |
| `ConvertTo-TimeFolder` | EXIF 时间串 → `YYYY-MM-DD` 等 | 格式不符/年份越界 → fallback |
| `Format-GpsFolder` | 十进制度 → `N31.23_E121.47` | 由调用方保证只在有 GPS 时调用 |
| `ConvertFrom-GpsString` | 解析 `31 deg 14' 4.20" N` | 解析不出 → `$null` |
| `Get-MediaFileList` | 递归列白名单扩展名文件 | 无权限目录 → 静默跳过 |
| `Get-NonMediaFileList` | 递归列非白名单文件（只用于提示） | 同上 |
| `Move-ToUniquePath` | 移动 + 重名加 `_1`，返回最终路径 | 目标被占用 → 继续加序号 |
| `Write-Section` / `Show-IgnoredFiles` | 输出格式 | — |

## 3. 常见改动怎么做

### 3.1 增加第四层维度（示例：按镜头型号）

以「主目录\设备\镜头\时间\地点」为例，需要改三处：

**① `Common.ps1` 加一个格式化函数**

```powershell
function ConvertTo-LensFolder {
    param([string]$Lens, [string]$Fallback = '无数据')
    # 镜头名里常有 "24-70mm F2.8" 这种带空格/斜杠的串，交给通用净化
    return ConvertTo-SafeFolderName -Name $Lens -Fallback $Fallback
}
```

**② `Classify.ps1` 的 `$tagList` 加标签**

```powershell
$tagList = @(
    'FileType', 'MIMEType', 'Make', 'Model', 'LensModel',   # ← 新增 LensModel
    ...
)
```

**③ `Classify.ps1` 组装路径的地方插入一层**

```powershell
$lens = ConvertTo-LensFolder -Lens (Get-ExifField -InputObject $item -Names @('LensModel','LensID'))
$destDir = Join-Path $Library $device | Join-Path -ChildPath $lens |
           Join-Path -ChildPath $timeFolder | Join-Path -ChildPath $locationFolder
```

**④ 在 `tests\run-tests.ps1` 里加断言**，并给测试照片写入 `-LensModel=...`。

> 改层级后，旧库的结构和新库不一致。要么一次性重跑（复制模式，先在临时目录验证），要么用 `-Root` 指向新库做对比。这个项目没有内置迁移器，是有意的：批量搬动已有照片风险高，留给用户自己决定。

### 3.2 把地点换成地名

替换 `Format-GpsFolder` 的调用处，改成查表：

```powershell
# 离线城市表，格式: "31.23,121.47" -> "上海-浦东"
$cityTable = Import-Csv (Join-Path $RepoRoot 'data\cities.csv')

$locationFolder = if ($hasGps) {
    $key = '{0:0.00},{1:0.00}' -f $lat, $lon
    $hit = $cityTable | Where-Object { $_.Key -eq $key } | Select-Object -First 1
    if ($hit) { $hit.City } else { Format-GpsFolder -Latitude $lat -Longitude $lon }
} else { $NA }
```

注意：`Where-Object` 在几千个城市上做线性查找会慢，改用哈希表 `@{ $key = '上海-浦东' }`。

### 3.3 支持新的文件类型

只改 `Common.ps1` 顶部的两个数组：

```powershell
$script:MediaExtensions += @('.3fr', '.iiq')          # 扩展名
$script:MediaFileTypes  += @('3FR', 'IIQ')            # exiftool 的 FileType
```

去重、分类都会自动跟上 —— 它们都读这两个数组。若新格式 ExifTool 不支持，文件会落进 `认不出格式`，这时只能补 MIME/FileType 映射。

### 3.4 侧车文件跟随主文件

`-r` 扫描之外，再对每个媒体文件找同名 `.xmp` / `.aae` / `.thm`，分类后一起复制：

```powershell
foreach ($sidecarExt in @('.xmp', '.aae')) {
    $sidecar = [System.IO.Path]::ChangeExtension($src, $sidecarExt)
    if (Test-Path -LiteralPath $sidecar) {
        Copy-Item -LiteralPath $sidecar -Destination $destDir
    }
}
```

目前**没有实现**，因为侧车文件不在白名单里，去重阶段也不会算它；如果加了，要同时决定"侧车文件算不算重复键"。

## 4. 踩坑记录（这些写法不是随手写的）

### 4.1 `@($raw | ConvertFrom-Json)` 会把数组再套一层

PowerShell 5.1 里：

```powershell
$x = @('[{...},{...}]' | ConvertFrom-Json)
$x.Count        # 1，元素还是个数组
```

正确写法：

```powershell
$items = $raw | ConvertFrom-Json
if ($null -eq $items) { $items = @() }
elseif ($items -isnot [System.Array]) { $items = @($items) }
```

### 4.2 原生命令参数里的 `-Tag=1.23` 必须加引号

```powershell
& $exifTool -GPSLatitude=31.2345 file.jpg     # ❌ exiftool 收到 "-GPSLatitude" 和 ".2345"
& $exifTool "-GPSLatitude=31.2345" file.jpg   # ✅
```

PS 5.1 在把小数字面量当参数传时会拆开，报错是 `File not found - .2345`，很容易误判成文件问题。

### 4.3 捕获原生命令输出会按 GB2312 解码

```powershell
$out = & $exifTool -j .        # ❌ 中文文件名变乱码
```

`[Console]::OutputEncoding` 是 GB2312，ExifTool 输出 UTF-8，解码即错。方案是写文件再读：

```powershell
$null = cmd /c "$exifTool -j ... > `"$jsonPath`""
$raw = Get-Content -LiteralPath $jsonPath -Raw -Encoding UTF8
```

### 4.4 传给 exiftool 的中文路径要避开命令行

命令行参数在 Windows 上会触发 `Warning: FileName encoding must be specified`，甚至写错文件。解法是 `Push-Location` 到目标目录，用 `"."` 扫描、用文件名操作 —— 参数里只出现 ASCII。

### 4.5 脚本必须存成 UTF-8 with BOM

PowerShell 5.1 读无 BOM 的 UTF-8 文件会按 ANSI 解析，中文注释和字符串变问号。**追加 BOM 要按字节做**，不要 `Get-Content | Set-Content -Encoding UTF8` 这种往返（会二次编码）：

```powershell
$b = [IO.File]::ReadAllBytes($p)
if (-not ($b[0] -eq 0xEF -and $b[1] -eq 0xBB -and $b[2] -eq 0xBF)) {
    $out = New-Object byte[] ($b.Length + 3)
    $out[0]=0xEF; $out[1]=0xBB; $out[2]=0xBF
    [Array]::Copy($b, 0, $out, 3, $b.Length)
    [IO.File]::WriteAllBytes($p, $out)
}
```

### 4.6 bat 里不要写 `chcp 65001`

`chcp` 改变代码页后，cmd 会按旧字节偏移重读批处理文件，后面的命令直接错乱（表现为 `'p' 不是内部或外部命令`）。bat 内容保持 **纯 ASCII + CRLF**，脚本名也用 ASCII，中文只出现在 `echo` 之外的 ps1 里。

### 4.7 `echo ... -> [xxx]` 会创建文件

`>` 在 `echo` 行里是重定向。写提示时用 `goes to` 之类的词，或转义 `^>`。

### 4.8 `Get-ChildItem -Include` 在目录树上不生效

```powershell
Get-ChildItem -LiteralPath $dir -Recurse -Include *.txt    # ❌ 返回目录本身
Get-ChildItem -LiteralPath $dir -Recurse -File |
    Where-Object { $_.Extension -eq '.txt' }               # ✅
```

`-Include` 只在路径带通配符（或配合 `-Recurse` 的特定形式）时才按预期过滤。

## 5. 测试

```powershell
powershell -ExecutionPolicy Bypass -File .\tests\run-tests.ps1
powershell -ExecutionPolicy Bypass -File .\tests\run-tests.ps1 -Keep   # 保留临时库
```

设计原则：

- **不 mock ExifTool**：夹具是真实 JPEG（`System.Drawing` 生成）+ ExifTool 真实写入的 EXIF
- **子进程跑脚本**：`& powershell -File ...`，验证的是用户实际执行的路径，包括参数解析和退出码
- **断言到具体路径**：不只断言"复制了 3 个"，而是断言 `主目录\Canon EOS R6\2024-05-10\N31.23_E121.47\canon_full.jpg` 存在
- **失败退出码 1**：可以直接接进 CI

加测试用例的模板：

```powershell
# 造文件
$p = Join-Path $Inbox 'case_x.jpg'
New-Jpeg -Path $p -Color ([System.Drawing.Color]::FromArgb(1,2,3))
Set-Exif -RelativePath 'case_x.jpg' -Tags @('-Make=Test', '-Model=TestCam')

# 期待
Assert-PathExists -Path (Join-Path $Library 'Test TestCam\无数据\无数据\case_x.jpg') -Message 'xxx 场景'
```

## 6. 发布流程

1. 改完跑 `tests\run-tests.ps1`，必须 25/25 且退出码 0
2. `CHANGELOG.md` 加一节（Keep a Changelog 风格）
3. `git tag v1.x.y && git push --tags`
4. 打 zip（可选）：`Compress-Archive -Path src,bin,tests,docs,README.md,LICENSE,config.example.ps1 -DestinationPath PhotoSorter-1.x.y.zip`

版本号约定：`主版本` 不兼容的目录结构变化；`次版本` 新增能力；`修订` 修 bug。

## 7. 移植到 macOS / Linux 的注意点

- 4.3 / 4.4 两个坑在非 Windows 上不存在，可以直接 `& $exifTool` 捕获输出
- `cmd /c` 要换成 `& $exifTool ... | Out-File -Encoding utf8`
- `Get-AppConfig` 的默认 `Root`、目录名（`待分类1` 等）建议换成本地化默认值或全部通过 config 指定
- `Copy-Item` / `Move-Item` 语义一致，但注意 Linux 上大小写敏感
- 测试里的 `System.Drawing` 在 .NET 6+ 需要 `System.Drawing.Common` 包，可改用 ImageMagick 生成夹具
